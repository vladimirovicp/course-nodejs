# Задание: основы Node.js

## Описание

Ваша задача — выполнить несколько простых заданий, чтобы изучить основы Node.js.

Сделайте форк [этого репозитория](https://github.com/AlreadyBored/node-nodejs-basics).

Задание содержит несколько вложенных папок внутри `src`. Ваша задача — реализовать необходимую функциональность внутри них.

## Технические требования

- Запрещено использовать любые внешние инструменты и библиотеки.
- Используйте Node.js версии `24.x.x` (`24.10.0` или выше).
- Не изменяйте сигнатуры заранее написанных функций (например, не переименовывайте их, не делайте синхронными и т. д.).
- По возможности отдавайте предпочтение асинхронному API.

## Подзадачи

### Файловая система (`src/fs`)

Вам нужно реализовать несколько функций в соответствующих файлах.

- `create.js` — реализуйте функцию, которая создаёт новый файл `fresh.txt` с содержимым `I am fresh and young` внутри папки `files` (если файл уже существует, должно быть выброшено `Error` с сообщением `FS operation failed`).
- `copy.js` — реализуйте функцию, которая копирует папку `files` со всем её содержимым в папку `files_copy` на том же уровне (если папка `files` не существует или папка `files_copy` уже была создана, должно быть выброшено `Error` с сообщением `FS operation failed`).
- `rename.js` — реализуйте функцию, которая переименовывает файл `wrongFilename.txt` в `properFilename` с расширением `.md` (если файла `wrongFilename.txt` нет или `properFilename.md` уже существует, должно быть выброшено `Error` с сообщением `FS operation failed`).
- `delete.js` — реализуйте функцию, которая удаляет файл `fileToRemove.txt` (если файла `fileToRemove.txt` нет, должно быть выброшено `Error` с сообщением `FS operation failed`).
- `list.js` — реализуйте функцию, которая выводит в консоль массив всех имён файлов из папки `files` (если папка `files` не существует, должно быть выброшено `Error` с сообщением `FS operation failed`).
- `read.js` — реализуйте функцию, которая выводит в консоль содержимое файла `fileToRead.txt` (если файла `fileToRead.txt` нет, должно быть выброшено `Error` с сообщением `FS operation failed`).

### Интерфейс командной строки (`src/cli`)

Вам нужно реализовать несколько функций в соответствующих файлах.

- `env.js` — реализуйте функцию, которая разбирает переменные окружения с префиксом `RSS_` и выводит их в консоль в формате `RSS_name1=value1; RSS_name2=value2`.
- `args.js` — реализуйте функцию, которая разбирает аргументы командной строки (они передаются в формате `--propName value --prop2Name value2`, валидировать их не нужно) и выводит их в консоль в формате `propName is value, prop2Name is value2`.

### Модули (`src/modules`)

Вам нужно выполнить рефакторинг файла (при необходимости можно добавить дополнительные импорты).

- `cjsToEsm.cjs` — перепишите его в эквивалентной нотации ECMAScript (и переименуйте в `esm.mjs`).

### Хеширование (`src/hash`)

Вам нужно реализовать несколько функций в соответствующих файлах.

- `calcHash.js` — реализуйте функцию, которая вычисляет SHA256-хеш для файла `fileToCalculateHashFor.txt` и выводит его в консоль в виде `hex`, используя Streams API.

### Потоки (`src/streams`)

Вам нужно реализовать несколько функций в соответствующих файлах.

- `read.js` — реализуйте функцию, которая читает содержимое файла `fileToRead.txt` с помощью `Readable Stream` и выводит его в `process.stdout`.
- `write.js` — реализуйте функцию, которая записывает данные из `process.stdin` в файл `fileToWrite.txt` с помощью `Writable Stream`.
- `transform.js` — реализуйте функцию, которая читает данные из `process.stdin`, переворачивает текст с помощью `Transform Stream`, а затем выводит его в `process.stdout`.

### Zlib (`src/zip`)

Вам нужно реализовать несколько функций в соответствующих файлах.

- `compress.js` — реализуйте функцию, которая сжимает файл `fileToCompress.txt` в `archive.gz`, используя `zlib` и Streams API.
- `decompress.js` — реализуйте функцию, которая распаковывает `archive.gz` обратно в `fileToCompress.txt` с тем же содержимым, которое было до сжатия, используя `zlib` и Streams API.

### Worker Threads (`src/wt`)

Вам нужно реализовать несколько функций в соответствующих файлах.

- `worker.js` — дополните данную функцию так, чтобы она работала с данными, полученными из главного потока, и реализуйте функцию, которая отправляет результат вычисления обратно в главный поток.
- `main.js` — реализуйте функцию, которая создаёт количество worker threads, равное числу логических ядер CPU хост-машины, из файла `worker.js`, а также умеет отправлять данные в эти потоки и получать из них результат вычисления. В каждый `worker` нужно отправить возрастающее число, начиная с `10`. Например: на хост-машине с **4** ядрами нужно создать **4** worker-потока и отправить **10** первому `worker`, **11** второму, **12** третьему, **13** четвёртому. После завершения всех workers функция должна вывести в консоль массив результатов. Результат представляет собой массив объектов с двумя свойствами:
  - `status` — `'resolved'`, если значение успешно получено от `worker`, или `'error'`, если в `worker` произошла ошибка.
  - `data` — значение от `worker` в случае успеха или `null` в случае ошибки в `worker`.

Результаты в массиве должны идти в том же порядке, в котором были созданы workers.

### Дочерние процессы (`src/cp`)

Вам нужно реализовать несколько функций в соответствующих файлах.

- `cp.js` — реализуйте функцию `spawnChildProcess`, которая принимает массив аргументов `args` и создаёт дочерний процесс из файла `script.js`, передавая ему эти `args`. Эта функция должна создать IPC-канал между `stdin` и `stdout` мастер-процесса и дочернего процесса:
  - `stdin` дочернего процесса должен получать ввод из `stdin` мастер-процесса.
  - `stdout` дочернего процесса должен отправлять данные в `stdout` мастер-процесса.
